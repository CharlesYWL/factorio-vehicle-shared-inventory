# Vehicle Shared Inventory

Factorio 2.0 / Space Age 模组。

[English](./README.md) | **中文**

坐在蜘蛛机甲（或汽车、坦克）里铺蓝图时很别扭：建造机器人只认载具后备箱，玩家背包里的材料完全用不上，必须反复下车倒货。本模组自动把缺的材料送进后备箱，下车时再还回来。

## 功能

- **自动补料** —— 扫描载具建造范围内的实体幽灵、**地板幽灵**、模块请求与升级请求，只搬真正缺的部分。
- **悬崖炸药** —— 待爆破的悬崖属于中立阵营且不产生幽灵，需单独探测，会自动补给对应炸药。
- **共享机器人** —— 把背包里的建造机器人借给载具，补到机器人站容量上限；**建造或拆除**任一有任务时触发，闲置载具不会掏空你的库存。优先借高品质的。
- **溢出回收** —— 后备箱空间不足时，把超出上车基线的拆除所得搬回玩家背包，避免机器人因装不下而停工。只回收你背包里已有的品类，弹药、燃料、机器人与当前建造所需材料永不回收。
- **记账式归还** —— 离开载具时只归还本模组借出的物品，**载具原有物资永远不会被拿走**。
- **品质感知** —— 不同 quality 的物品独立计数，绝不混淆。
- **广泛载具支持** —— 蜘蛛机甲、汽车、坦克，按 prototype type 判定，模组载具自动兼容。
- **性能优先** —— 脏标记缓存 + 规模探测，空闲时主循环近似 O(1)。

## 为什么不是真正的「合并库存」

Factorio 引擎中载具机器人站的取货来源是硬编码的（`car_trunk` / `spider_trunk`），Lua API 无法注入第二个来源；`LinkedContainerPrototype` 的共享也只对**同 prototype 的容器**生效，角色与载具都不符合条件。

所以真正的库存合并在 API 层面**不可能实现**，本模组采用**按需搬运**来模拟。

## 设置

| 设置 | 默认 | 说明 |
|---|---|---|
| 启用背包共享 | 开 | 总开关（按玩家） |
| 共享建造机器人 | 开 | 借出机器人补到机器人站容量 |
| 更新间隔 | 15 tick | 可选 5 / 15 / 30 / 60 |
| 离开载具时归还借出物品 | 开 | 关闭则单向借出 |
| 后备箱将满时回收物品 | 开 | 把拆除所得搬回玩家背包 |
| 后备箱剩余空间阈值 | 20% | 空格低于此比例时开始回收 |
| 要求载具装有机器人站 | 开 | 关闭后无机器人站也共享 |
| 支持的载具 | 蜘蛛机甲、汽车与坦克 | 启动设置 |
| 单次扫描幽灵上限 | 5000 | 全局设置 |

> 新增或改动设置项需要**完全重启 Factorio**，仅重新读档无效 —— 设置是在启动阶段注册的。

## 安装（开发中）

把整个文件夹（或打包成 `vehicle-shared-inventory_0.1.0.zip`）放入：

```
%APPDATA%\Factorio\mods\
```

文件夹名必须为 `vehicle-shared-inventory_0.1.0`。

开发时推荐用软链接：

```powershell
New-Item -ItemType SymbolicLink `
  -Path "$env:APPDATA\Factorio\mods\vehicle-shared-inventory_0.1.0" `
  -Target "<本仓库路径>"
```

## 诊断

坐在载具里，在控制台执行：

```
/vsi-debug
```

会输出：玩家是否被追踪、通电机器人站的半径、范围内幽灵数量、机器人容量与当前数量、以及算出来缺什么。

## 已知限制

- 遥控蜘蛛（未乘坐）时不生效，必须真的坐进去。
- 不支持火车车厢。
- 不自动补给弹药与燃料栏。
- 下车时不会召回**正在飞行或正搬着货**的机器人。它们留在载具里而不是被销毁，所以归还可能不完整 —— 但不会丢东西。

完整设计见 [SPEC.md](./SPEC.md)。
